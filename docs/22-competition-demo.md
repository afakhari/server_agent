# 22 · نسخه مسابقه: دسترسی مهمان بدون کلید

این مسیر برای نمایش قابلیت‌های **شبیه‌سازی‌شده** Sentinel در مسابقه است، نه ارائه دسترسی ناشناس به حساب واقعی لیارا.

## تجربه بازدیدکننده

هر بازدیدکننده سایت را با HTTPS باز می‌کند و مستقیماً وارد گفت‌وگوی Demo می‌شود. نیازی به ورود، رمز Caddy، کلید Sentinel یا توکن API لیارا در مرورگر نیست. می‌تواند با پیشنهادهای آماده، سناریوهای خطا و بررسی آمادگی پروژه نمونه را امتحان کند و نتیجه اقدام شبیه‌سازی‌شده را با یک دکمه تأیید ببیند. داده‌ها واقعی نیستند و هیچ تغییر زنده‌ای ارسال نمی‌شود.

هویت دمو از یک کوکی تصادفی، `HttpOnly` و `SameSite=Lax` ساخته می‌شود. هر مرورگر تاریخچه و مجوزهای شبیه‌سازی خودش را دارد. با پاک‌شدن کوکی، دسترسی به تاریخچه قبلی از دست می‌رود. این کوکی مجوز هیچ عملیات واقعی نیست.

## تنظیم سرور

`compose.server.yaml` فایل `deploy/server/Caddyfile.competition` را به Caddy می‌دهد که **Basic Auth ندارد** و مسیرهای مدیریتی واقعی را در پراکسی با 403 رد می‌کند. سرور همچنان در `SENTINEL_EXPOSURE_MODE=private-server` اجرا می‌شود؛ این حالت کلید تصادفی حداقل ۳۲ نویسه‌ای و دیتابیس روی volume و فرانت‌اند buildشده می‌خواهد. کلید فقط در فایل محیطی محرمانه `deploy/server/app.env` می‌ماند، نه در سایت یا جاوااسکریپت.

`deploy/server/caddy.env` در نسخه مسابقه فقط به `SENTINEL_DOMAIN` نیاز دارد. تنظیمات `SENTINEL_ALLOW_LIVE_WRITES=false` و `SENTINEL_CLI_DEPLOY_ENABLED=false` باید حفظ شوند. توکن لیارا برای دمو لازم نیست؛ بهتر است روی استقرار عمومی مسابقه اصلاً تنظیم نشود.

```bash
python -m pytest -q
cd frontend && npm ci && npm run build && cd ..
python scripts/check_server_release.py
docker compose -f compose.server.yaml config --quiet
docker compose -f compose.server.yaml build
docker compose -f compose.server.yaml up -d
```

این دستورات **فقط روی سرور تحت مدیریت اپراتور** و پس از آماده‌شدن فایل‌های `app.env` و `caddy.env` اجرا می‌شوند. Commit روی GitHub به معنی استقرار یا سلامت سایت زنده نیست.

## آزمون پذیرش

در مرورگر بدون سابقه، سایت باید بدون درخواست نام کاربری و رمز باز شود؛ انتخاب «سایتم خطای ۵۰۰ می‌دهد» باید گزارش مبتنی بر داده نمونه بسازد؛ تأیید نتیجه دمو نباید پروژه واقعی را ری‌استارت کند. مرورگر دوم نباید تاریخچه مرورگر اول را ببیند. درخواست بدون مجوز به مسیرهای واقعی لیارا باید 403 بدهد. فقط بعد از تست `npm run build`، `pytest`، HTTPS و بازکردن سایت در دو مرورگر مجزا می‌توان درباره آماده‌بودن نسخه آنلاین قضاوت کرد.

فایل `deploy/server/Caddyfile` که برای اپراتور خصوصی Basic Auth دارد، حذف نشده است. اگر استقرار خصوصی خواسته شود باید mount مربوط در Compose و الزامات تست همان حالت دوباره بررسی شود.
