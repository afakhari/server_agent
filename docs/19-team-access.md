# 19 · اتصال ایمن به منابع تیم لیارا با teamID

**تاریخ بازبینی: 2026-10-23.** مبنا: [OpenAPI رسمی PaaS](https://github.com/liara-cloud/openapi/blob/main/spec/paas.yaml)، [CLI رسمی](https://github.com/liara-cloud/cli/blob/master/src/base.ts)، [whoami CLI](https://github.com/liara-cloud/cli/blob/master/src/commands/whoami.ts)، و تصویر کنسول ارائه‌شده توسط مالک.

## نتیجه بررسی

- در OpenAPI PaaS پارامتر `teamID` برای دسترسی به سرویس‌های تیم ذکر شده است. روش دقیق افزودن آن به درخواست‌های REST در spec با جزئیات شرح داده نشده، **اما خود Liara CLI** در `src/base.ts` آن را برای تمام HTTP requestها با `searchParams.set('teamID', config['team-id'] || '')` به URL اضافه می‌کند.
- احراز هویت مستقل از teamID، از طریق `Authorization: Bearer <token>` انجام می‌شود. **teamID توکن نیست، به‌تنهایی مجوز نیست، و نباید جای Authorization قرار گیرد.**
- در CLI، `liara team use` یا `--team-id` تیم پیش‌فرض/موقت را انتخاب می‌کند. اگر تیم مشخص نشود، حساب شخصی استفاده می‌شود؛ بسته به مجوزهای توکن، انتخاب تیم ممکن است کار کند یا 401/403/404 دریافت شود.
- نمایش شناسه تیم در صفحه API کنسول و مشاهده برنامه متفاوت در فهرست API بدون teamID، نشانه‌ای قوی از متفاوت بودن context است؛ بدون live probe نتیجه قطعی نیست.

## چرا برای Sentinel مهم است؟

پنل تیم پروژه آزمایشی Python را نشان می‌دهد، اما توکن بدون teamID برنامه Node دیگری را در فهرست برگردانده است. نباید برای دورزدن این تفاوت برنامه دوم ایجاد کنیم یا Python را روی Node موجود منتشر کنیم.

## تغییر کد

- `sentinel/liara.py` گزینه سرور-محور `LIARA_TEAM_ID` را از محیط می‌خواند. کلاینت HTTPX پارامتر `teamID` را **هم برای GET و هم برای POST multipart و POST JSON** به URL اضافه می‌کند؛ پارامترهای `since/page/count` نیز حفظ می‌شوند.
- `scripts/run_local.py --team-id` شناسه را اعتبارسنجی و فقط برای اجرای همان سرور تنظیم می‌کند. این داده از UI یا مدل دریافت نمی‌شود.
- در رابط وضعیت `Live TEAM API mode` از `Live PERSONAL API mode` جدا دیده می‌شود.
- مجوزهای یک‌بارمصرف عملیات Live با context تیم پیوند داده می‌شوند. تغییر teamID پس از صدور مجوز، مجوز قدیمی را بی‌اعتبار می‌کند.
- مسیر CLI اختصاصی Sentinel فعلاً برای تیم مسدود است؛ مسیر API مستقیم برای Windows و تیم مناسب‌تر است.
- این تغییر **حساب تیمی جدید نمی‌سازد و به‌تنهایی مجوز دسترسی به تیم اعطا نمی‌کند**.

## راهنمای دقیق صاحب پروژه روی Windows CMD

۱. در کنسول لیارا تیم موردنظر را از منوی بالای صفحه انتخاب کن. در صفحه API همان تیم بخش «شناسه تیم» را پیدا کن و فقط **ID** را کپی کن؛ نه توکن را. از نام شبکه خصوصی، نام برنامه و شناسه حساب به‌جای teamID استفاده نکن.

۲. سرور جاری Sentinel را با Ctrl+C متوقف کن. ریپو را به‌روز کن:

```cmd
cd /d D:\projs\Liara\server_agent
git pull origin main
.venv\Scripts\activate.bat
```

۳. با **توکن فعلی** ابتدا فقط دسترسی خواندنی را آزمایش کن:

```cmd
python scripts\run_local.py --mode read --team-id TEAM_ID_FROM_CONSOLE --project sentinel-sandbox-01
```

به جای `TEAM_ID_FROM_CONSOLE` شناسه واقعی تیم را **فقط روی کامپیوتر خودت** قرار بده. اگر برنامه تیم نام دیگری دارد، `--project` را هم مطابق پنل تغییر بده. توکن API را فقط در prompt مخفی وارد کن.

۴. در مرورگر `http://127.0.0.1:8000`، Ctrl+F5 بزن؛ Live را انتخاب کن. نشانگر باید `Live TEAM API mode` باشد. «نمایش برنامه‌های حساب لیارا» را بزن. اگر پروژه موردنظر در فهرست بود، انتخاب و «شروع بررسی شواهد» را اجرا کن.

۵. نتیجه‌ها:

| نتیجه | تفسیر عملی |
|---|---|
| پروژه تیم در فهرست دیده می‌شود | حساب/توکن با teamID توانست منابع تیم را بخواند؛ **هنوز دسترسی انتشار ثابت نشده** |
| فقط برنامه حساب شخصی دیده می‌شود | احتمال عدم اثرگذاری teamID، شناسه تیم نادرست یا پاسخ ناسازگار؛ بدون write بررسی شود |
| HTTP 401 | توکن نامعتبر/منقضی یا نوع مجوز مناسب نیست؛ توکن را در کنسول بررسی کن |
| HTTP 403 | احتمال نبود مجوز عضویت یا عمل روی منابع تیم؛ نقش/مجوز تیم را بررسی کن |
| HTTP 404 | برنامه در context انتخاب‌شده پیدا نشد یا مسیر API متفاوت است؛ فهرست تیم و نام دقیق را کنترل کن |

۶. اگر توکن فعلی منابع تیم را نمی‌بیند ولی کاربر در تیم عضو است، از صفحه API **همان تیم** (همان صفحه‌ای که ID تیم را نشان می‌دهد) یک کلید کوتاه‌عمر **در صورت مجازبودن** بساز؛ کلید قبلی را بی‌دلیل حذف نکن. هیچ کلیدی در چت، ریپو یا تصویر عمومی قرار نده. سپس فقط مرحله Read را تکرار کن.

۷. تا وقتی پروژه تیم و پلتفرم صحیح از API خوانده نشده و پلن/بودجه شخصاً تأیید نشده، **`--mode test-api` و دکمه انتشار واقعی را اجرا نکن.**

## آزمون‌های کد بدون لیارا

`tests/test_liara.py` شامل fixture تیمی ساختگی برای GET projects، logs، releases و آپلود multipart است؛ `tests/test_security.py` تفکیک fingerprint مجوزهای تیم/شخصی را بررسی می‌کند. هیچ شناسه تیم واقعی در fixture وجود ندارد. تست زنده این تغییر هنوز انجام نشده است؛ CI نیز به‌درخواست مالک اضافه نشده است.

## اصلاح خطای Windows CMD: No module named sentinel
اگر با `python scripts\\run_local.py --mode read --team-id TEAM_ID ...`
خطای `Preflight failed: No module named 'sentinel'` گرفتی، این خطا ناشی از
Python import path در اجرای مستقیم فایل از پوشه `scripts` بوده است و
با اضافه‌کردن پوشه ریشه پروژه به `sys.path` برطرف شد.

پس از `git pull origin main` هر دو روش زیر معتبرند:
- `python scripts\\run_local.py --mode read --team-id REAL_TEAM_ID --project sentinel-sandbox-01`
- `python -m scripts.run_local --mode read --team-id REAL_TEAM_ID --project sentinel-sandbox-01`

`REAL_TEAM_ID` را **با مقدار واقعی پایین صفحه API تیم** جایگزین کن.
نوشتن خود `TEAM_ID` یا `REAL_TEAM_ID` به‌جای مقدار واقعی، مجاز نیست.
برای دسترسی به تیم ممکن است توکن فعلی کافی باشد؛ ابتدا فقط Read را بررسی کن.
